1. Overview: Your Options

Since you already have a web server using port 443, you have three main approaches:

1 Nginx SNI Routing (Port Multiplexing) - RECOMMENDED

How it works: Nginx sits in front and inspects the TLS Server Name Indication (SNI) field without decrypting traffic, then routes connections to either your web server or Xray based on the domain name.

✓ Pros
  • Uses standard port 443
  • Bypasses most port restrictions
  • Both services work simultaneously
  • Most GFW-resistant (443 is HTTPS)
  • Professional setup
✗ Cons
  • Requires Nginx reconfiguration
  • More complex initial setup
  • Need specific Nginx modules
  • Requires understanding SNI routing

2 Use Alternative Port (e.g., 8443, 2053)

How it works: Run Xray REALITY on a different port while your web server keeps port 443.

✓ Pros
  • Simple setup
  • No web server changes needed
  • Easy to understand
  • Quick to implement
✗ Cons
  • Some networks block non-standard ports
  • Slightly less stealthy
  • May not work in restrictive environments
  • Easier to detect (non-443 TLS)

3 "Steal Yourself" Configuration

How it works: Xray REALITY uses your own domain and TLS certificate, forwarding unmatched traffic to your web server on localhost.

✓ Pros
  • Very stealthy
  • Uses your real domain/certificate
  • May provide more stable connection
  • Single port solution
✗ Cons
  • Requires domain ownership
  • More complex configuration
  • Xray handles port 443 directly
  • Need to move web server to localhost port
Our Recommendation: Use Option 1 (Nginx SNI Routing) for the best balance of stealth, functionality, and GFW resistance. This guide will focus primarily on this method, with instructions for Option 2 as well.

2. Option 1: Nginx SNI Routing (Recommended)

How SNI Routing Works

Server Name Indication (SNI) is an extension to TLS that allows a client to specify which hostname it's trying to reach during the TLS handshake. Nginx can inspect this field before decrypting the connection and route traffic accordingly:

Client → Port 443 → Nginx (reads SNI) → Routes based on domain name
                              ↓
                    If SNI = proxy.example.com → Xray REALITY
                    If SNI = www.example.com → Your Web Server
                    If SNI = anything else → Xray REALITY (stealth)

Architecture Diagram


┌─────────────────────────────────────────────────────────┐
│                     Port 443                            │
│                   (Public Interface)                    │
└────────────────────┬────────────────────────────────────┘
                     │
              ┌──────▼──────┐
              │   Nginx     │
              │   Stream    │ (Inspects SNI with ssl_preread)
              │   Module    │
              └──────┬──────┘
                     │
         ┌───────────┴───────────┐
         │                       │
    ┌────▼─────┐          ┌─────▼──────┐
    │  Xray    │          │    Your    │
    │ REALITY  │          │    Web     │
    │127.0.0.1 │          │   Server   │
    │  :8443   │          │127.0.0.1   │
    └──────────┘          │   :8080    │
                          └────────────┘

Key Technical Points

  • ssl_preread: Nginx examines TLS ClientHello without decrypting
  • No SSL termination: Traffic passes through as encrypted streams
  • Zero latency overhead: Simple TCP forwarding based on SNI
  • Transparent routing: Each backend service handles its own TLS
Important: Once Nginx's stream module listens on port 443, your web server must move to a different port (like 8080) and accept connections from Nginx via reverse proxy. Don't worry - we'll configure this properly!

3. Option 2: Use Alternative Port

If you want a simpler setup and don't mind using a non-standard port:

Quick Setup Steps

  1. Keep your web server on port 443 (no changes needed)
  2. Configure Xray REALITY to listen on an alternative port
  3. Open the alternative port in your firewall
  4. Configure your router to forward the port

Recommended Alternative Ports

Port Description Notes
8443 Common alternative HTTPS Widely used, generally not blocked
2053 Cloudflare-friendly Less likely to be blocked in some regions
2096 Cloudflare-friendly Good alternative
2087 Cloudflare-friendly Another option
Consideration: Port 443 is NOT required for Xray REALITY to function. However, some restrictive networks (hotels, corporate firewalls, strict ISPs in China) may block non-standard ports. Port 443 offers the best compatibility.

4. Option 3: "Steal Yourself" Configuration

This advanced configuration allows REALITY to use your own domain's TLS certificate:

Requirements

  • Own a domain name (e.g., example.com)
  • Subdomain pointing to your server (e.g., proxy.example.com)
  • Valid TLS certificate for your domain
  • Web server (Nginx/Caddy) listening on localhost port

How It Works

1. Xray listens on port 443
2. REALITY uses your domain (proxy.example.com) as the "dest"
3. Authenticated clients connect to Xray proxy
4. Non-authenticated traffic gets forwarded to your web server on localhost:4123
5. To outsiders, it looks exactly like a normal HTTPS website
When to use this: Best for advanced users who want maximum stealth and already have domain management experience. We'll provide configuration examples later in this guide.

5.5 Choose Your Destination (dest) Website

The "dest" parameter is crucial - it's the website that Xray REALITY mimics. When the GFW probes your server, it sees traffic that looks identical to accessing this legitimate website.

  • ✓ Should not redirect (avoid using apex domains that redirect to www)
  • ✓ Should not be blocked by GFW
  • ✓ Should not contain illegal content
  • ✓ Preferably geographically close to your server (lower latency)

6. Detailed Setup: Nginx SNI Method

Step 1: Backup Your Current Configuration

# Backup current Nginx config
sudo cp /etc/nginx/nginx.conf /etc/nginx/nginx.conf.backup
sudo cp -r /etc/nginx/sites-enabled /etc/nginx/sites-enabled.backup

# Backup web server files (if needed)
sudo cp -r /var/www/html /var/www/html.backup

Step 2: Move Web Server to Port 8080

Edit your existing Nginx site configuration:

# Find your site config (commonly in /etc/nginx/sites-available/)
sudo nano /etc/nginx/sites-available/default
# or
sudo nano /etc/nginx/sites-available/yourdomain.com

Change the server block:

# OLD CONFIGURATION (before):
server {
    listen 443 ssl http2;
    server_name yourdomain.com;

    ssl_certificate /path/to/cert.pem;
    ssl_certificate_key /path/to/key.pem;

    # ... rest of config
}

# NEW CONFIGURATION (after):
server {
    listen 8080;  # Changed from 443 to 8080
    server_name yourdomain.com;

    # Remove SSL directives - no longer needed here
    # SSL will be handled by Nginx stream module

    # Add real IP handling (important!)
    set_real_ip_from 127.0.0.1;
    real_ip_header X-Forwarded-For;
    real_ip_recursive on;

    # ... rest of config stays the same
}
Important: Remove the SSL listen directive (443) and SSL certificate directives. The web server will receive plain HTTP from Nginx stream module (which already decrypted it).

Step 3: Configure Nginx Stream Module for SNI Routing

Create a new stream configuration file:

sudo nano /etc/nginx/stream.conf

Add the following configuration:

# /etc/nginx/stream.conf
# SNI-based routing for Xray REALITY and Web Server

# Define upstream servers
upstream xray_reality {
    server 127.0.0.1:8443;  # Xray REALITY listens here
}

upstream web_server {
    server 127.0.0.1:8080;  # Your web server listens here
}

# Map SNI to backend
map $ssl_preread_server_name $backend_name {
    yourdomain.com          web_server;    # Your actual domain → web server
    www.yourdomain.com      web_server;    # www version → web server
    default                 xray_reality;  # Everything else → Xray
}

# Main server block
server {
    listen 443 reuseport;
    listen [::]:443 reuseport;

    proxy_pass $backend_name;
    ssl_preread on;
    proxy_protocol on;  # Optional: preserves client IP
}
Configuration Explanation:
  • upstream blocks: Define backend servers (Xray and web server)
  • map directive: Routes based on SNI ($ssl_preread_server_name)
  • ssl_preread on: Enables SNI inspection without decryption
  • proxy_protocol: Passes client IP to backends (optional but recommended)
  • default: Unknown domains go to Xray (stealth mode!)

Step 4: Include Stream Config in Main Nginx Config

sudo nano /etc/nginx/nginx.conf

Add the stream block at the TOP LEVEL (outside and after the http block):

# /etc/nginx/nginx.conf

user www-data;
worker_processes auto;
pid /run/nginx.pid;

events {
    worker_connections 1024;
}

# HTTP block (your existing config)
http {
    include /etc/nginx/mime.types;
    default_type application/octet-stream;

    # ... your existing http config ...

    include /etc/nginx/sites-enabled/*;
}

# ADD THIS STREAM BLOCK (at the same level as http, not inside it!)
stream {
    include /etc/nginx/stream.conf;
}
Critical: The stream block must be at the same level as the http block, NOT inside it! This is a common mistake.

Step 5: Test Nginx Configuration

# Test configuration for syntax errors
sudo nginx -t

# Expected output:
# nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
# nginx: configuration file /etc/nginx/nginx.conf test is successful

# If successful, reload Nginx
sudo systemctl reload nginx

# Check status
sudo systemctl status nginx

Configuration Parameters Explained

Parameter Description Your Value
listen Listen on localhost (Nginx forwards here) 127.0.0.1
port Xray listening port (internal) 8443
id Client UUID (authentication) From xray uuid
flow XTLS flow type (must be Vision) xtls-rprx-vision
dest Destination website to mimic microsoft.com:443
serverNames Valid SNI names for clients ["microsoft.com"]
privateKey REALITY private key From xray x25519
shortIds Client identifiers (can distinguish users) ["", "0123456789abcdef"]
acceptProxyProtocol Accept client IP from Nginx true

Troubleshooting Connection Issues

Can't Connect from Client

Check:

  • Firewall allows port 443: sudo ufw status
  • Router port forwarding configured correctly
  • Xray is running: systemctl status xray
  • Nginx is running: systemctl status nginx
  • No errors in logs: journalctl -u xray -n 50
  • UUID matches between server and client
  • Public key in client matches the pair's public key

Web Server Not Accessible

Check:

  • Web server listening on 8080: netstat -tulpn | grep 8080
  • SNI mapping correct in stream.conf
  • Domain name resolves to server IP: nslookup yourdomain.com
  • Test direct access: curl http://localhost:8080

Xray Connected But No Internet

Check:

  • Server can access internet: curl google.com
  • Routing rules in Xray config
  • Check outbound settings (should be "freedom")
  • DNS settings in client

Common Issues and Solutions

Issue: "Nginx failed to start" after adding stream config

# Test config
sudo nginx -t

# Common causes:
# 1. Stream block inside http block (must be at same level)
# 2. Missing stream modules
# 3. Syntax error

# Verify modules
nginx -V 2>&1 | grep stream

# If modules missing, install nginx-full or nginx-extras
sudo apt install nginx-extras

Issue: "Connection refused" from client

# Debug checklist:

# 1. Port forwarding
# Log into router, verify 443 → your server IP

# 2. Firewall
sudo ufw status
sudo ufw allow 443/tcp

# 3. Services running
sudo systemctl status nginx
sudo systemctl status xray

# 4. Check if port is reachable from outside
# Use online port checker: https://www.yougetsignal.com/tools/open-ports/
# Enter your public IP and port 443

# 5. Test from another network (use phone with mobile data)
telnet YOUR_PUBLIC_IP 443

Issue: "TLS handshake failed" in client

# Possible causes:

# 1. Wrong server name
# Make sure client serverName matches one in server's serverNames array

# 2. Wrong public key
# Verify client has the correct public key (from xray x25519)

# 3. Dest website unreachable
# Test from server:
curl -I https://microsoft.com

# 4. Flow mismatch
# Both client and server must have: flow: "xtls-rprx-vision"

# Check Xray logs
sudo journalctl -u xray -n 50 --no-pager

Issue: Xray works but web server returns 502

# Web server not accepting connections on 8080

# 1. Verify web server is listening on 8080
sudo netstat -tulpn | grep 8080

# 2. Check web server config
sudo nginx -t  # If using Nginx as web server too

# 3. Check web server logs
sudo tail -f /var/log/nginx/error.log

# 4. Test direct connection
curl http://localhost:8080

# 5. Verify Nginx upstream config points to correct port
grep -r "upstream web_server" /etc/nginx/

Issue: "ssl_preread_server_name is empty"

# Client is not sending SNI

# 1. Verify client is configured to send SNI
# In client config, ensure serverName is set

# 2. Some old clients don't support SNI
# Update client software

# 3. Check Nginx stream config has ssl_preread on
grep "ssl_preread" /etc/nginx/stream.conf

Issue: High latency or slow speeds

# 1. Enable BBR congestion control
echo "net.core.default_qdisc=fq" | sudo tee -a /etc/sysctl.conf
echo "net.ipv4.tcp_congestion_control=bbr" | sudo tee -a /etc/sysctl.conf
sudo sysctl -p

# 2. Optimize Xray buffer size (in config.json)
# Add to streamSettings.sockopt:
"tcpKeepAliveInterval": 30,
"tcpFastOpen": true

# 3. Choose closer dest website
# Change dest to geographically closer site

# 4. Check server resources
htop
df -h
free -h

# 5. Test baseline speed
speedtest-cli
